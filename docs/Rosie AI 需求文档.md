# Rosie AI 需求文档

版本：v1.0  
文档类型：合并版 PRD  
来源：由 docs 目录下原有产品、接入、独立号码、规模化等文档整理合并  

## 1. 项目概述

Rosie AI 是面向中国中小商家和高频接电话业务人士的智能语音接线员。用户原手机号或座机保持不变，默认通过“无应答 / 忙线 / 不可及”条件呼叫转移，把漏接、忙线、关机或无信号场景转给 Rosie 幕后接入号。Rosie 在电话侧完成自动接听、防骚扰过滤、咨询问答、预约记录、重要来电转接和通话摘要推送。

产品核心不是传统 CRM，也不是云呼叫中心后台，而是一个低学习成本的“电话前台”。用户主要通过微信小程序完成开通、查看和续费，通过企业微信群机器人接收来电摘要、预约、骚扰拦截和异常提醒；微信订阅消息、钉钉和短信作为兜底渠道。

## 2. 产品定位

一句话定位：为小微经营者和业务人士提供 7 x 24 小时 AI 电话前台，帮用户少漏接、少被打扰、多留住有效客户。

Rosie 的产品边界必须清晰：Rosie 只处理客户主动打进来的电话，不做主动外拨电话，不做电销系统。产品价值是“帮你不错过客户、少被骚扰”，不是“替你骚扰客户”。

核心价值：

| 价值 | 说明 |
|------|------|
| 防漏接 | 忙时、非营业时间、无人接听时由 AI 接管来电 |
| 防骚扰 | 前置识别营销、贷款、POS、发票等无效来电，减少打扰 |
| 自动记录 | 通话录音、文字转写、摘要、关键信息结构化 |
| 自动预约 | 针对商家场景完成时间确认、项目确认和预约记录 |
| 零学习成本 | 微信扫码、支付、开通，企业微信群接收通知，不要求安装独立 App |

### 2.1 入站优先原则

- 默认只接入客户主动拨打商家原号码后，经无应答 / 忙线 / 不可及条件呼叫转移进入 Rosie 的电话。
- 不以主动拨打陌生客户、批量拨号、电话营销作为产品方向。
- “回电话”只能作为来电后的上下文动作，例如客户刚来电未说清、老板在通话详情中手动点击回拨，或商家对单次服务事项明确授权。
- 所有回拨都必须可追溯到原始来电、预约、订单或用户明确动作，并记录触发人、触发时间、触发原因。
- 不提供陌生号码导入后批量外呼、不提供自动获客外呼、不提供电销坐席工作台。

## 3. 目标用户

### 3.1 商家版用户

典型用户：

- 美发店、宠物店、牙科诊所、餐厅、家政、维修、搬家、开锁等线下商家。
- 老板或店长经常在服务客户，无法随时接电话。
- 不愿意学习复杂系统，不想维护独立 CRM。

主要诉求：

- 非营业时间也能接住潜在客户。
- 忙时不被电话打断。
- 自动记录预约人、手机号、时间、项目。
- 每天用微信看摘要和汇总即可。

### 3.2 业务人士版用户

典型用户：

- 销售、中介、自由职业者、个体服务者等高频电话人群。
- 每天接几十通电话，其中大量为骚扰或低价值来电。

主要诉求：

- 自动过滤骚扰电话。
- 保留重要来电记录、录音和文字转写。
- 紧急或高价值来电可以转接本人。
- 不需要预约能力或复杂店铺配置。

## 4. 用户痛点

| 痛点 | 表现 | 影响 |
|------|------|------|
| 漏接电话 | 忙时、休息时、服务客户时无法接听 | 流失潜客、错过预约和订单 |
| 电话打断工作 | 理发、维修、接待过程中频繁被打断 | 服务质量下降，老板疲惫 |
| 骚扰电话多 | POS、贷款、发票、推销机器人反复来电 | 浪费时间，增加情绪负担 |
| 软件学习成本高 | 不想下载 App，不想登录后台，不会设置复杂规则 | 开通转化率低，留存差 |
| 通话信息丢失 | 靠记忆或纸笔记录预约 | 出错、漏单、无法复盘 |

## 5. 产品目标

### 5.1 MVP 目标

- 让商家在 2 到 5 分钟内完成开通。
- 跑通“来电接听 -> 防骚扰 -> AI 对话 -> 通话记录 -> 微信推送”的完整闭环。
- 支持小规模真实商家试点，验证用户是否愿意为 30 元/月基础套餐付费。
- 端到端语音交互延迟控制在可接受范围，目标小于 1.5 秒。

### 5.2 商业化目标

- 商家版参考定价：30 元/月。
- 业务人士版参考定价：30 元/月。
- 老板授权声音克隆增值服务：+5 元/月。
- 单用户或单商家月度通信与 AI 成本在规模化后控制在 3 到 6 元区间。
- 中长期支持 3000 商家到 5 万用户规模。

### 5.3 非目标

- MVP 不做复杂 CRM。
- MVP 不做完整工单系统。
- MVP 不做多坐席人工客服中心。
- MVP 不把号码复用 IVR 作为默认体验，除非独立号码成本或供应受限。
- 不做主动外拨电话。
- 不做批量外呼、陌生号码营销、电话销售 CRM。
- 不做无上下文自动回拨。任何回拨都必须有真实来电、预约、订单或用户明确确认作为上下文。

## 6. 产品版本与套餐

| 套餐 | 目标用户 | 定价建议 | 核心功能 |
|------|----------|----------|----------|
| 商家版 | 线下小微商家 | 30 元/月 | 防骚扰、智能接听、预约、客户记录、通知、日报 |
| 业务人士版 | 销售、中介、自由职业者 | 30 元/月 | 防骚扰、录音、转写、摘要、重要来电转接 |
| 老板授权声音克隆 | 商家版增值服务 | +5 元/月 | 基于商家明确授权的声音样本生成品牌化接听音色 |

声音克隆服务边界：

- 默认不启用，必须由商家主动购买、录制并授权。
- 不用于冒充老板本人，应在开场中明确“我是 Rosie AI 前台”。
- 优先用于欢迎语、品牌问候、预约确认等低风险话术。
- 商家可随时关闭声音克隆并删除声音样本。
- 录音样本、生成音色和使用日志需要纳入隐私与授权管理。

## 7. 核心用户流程

### 7.1 开通流程

推荐流程：

1. 用户扫码进入微信小程序。
2. 微信授权登录并绑定手机号。
3. 选择套餐并通过微信支付。
4. 系统分配 Rosie 幕后接入号，该号码不要求客户公开使用。
5. 系统尝试通过运营商能力自动开通条件呼叫转移，默认只开启无应答、忙线、不可及转移，不启用无条件转移。
6. 如果自动开通失败，进入手动引导流程。
7. 用户完成测试来电，确认 Rosie 正常接听。

手动引导降级：

1. 小程序展示当前手机运营商对应的呼叫转移设置方式。
2. 提供一键拨号按钮，尽量减少用户输入。
3. 提供短视频或图文说明。
4. 用户点击“我已设置完成”后，系统发起测试。
5. 对不会操作的用户提供客服协助。

### 7.2 来电处理流程

1. 客户照常拨打商家原手机号或座机。
2. 商家正常响铃；若无应答、忙线、不可及，运营商将来电转到 Rosie 幕后接入号。
3. 特殊商家可选择公开 Rosie 专属号码，但这不是默认模式。
4. 系统识别被叫接入号和转接上下文，定位商家或用户配置。
5. Rosie 播放欢迎语并启动流式语音识别。
6. 前 5 秒进行骚扰关键词和行为识别。
7. 若判定为骚扰电话，直接挂断并记录黑名单。
8. 若为有效来电，进入 AI 对话。
9. 根据意图执行咨询、预约、投诉记录或人工转接。
10. 通话结束后生成摘要、结构化信息和推送。

### 7.3 商家日常使用流程

1. 商家正常经营，不需要打开后台。
2. Rosie 自动接听忙时或无人接听来电。
3. 每通有效来电后，商家优先收到企业微信群机器人通知。
4. 商家可在小程序查看录音、转写、摘要和关键信息。
5. 每日晚上收到来电汇总。
6. 月末收到续费提醒和本月价值报告。

## 10. 通知策略

通知渠道优先级：

| 优先级 | 渠道 | 用途 | 说明 |
|--------|------|------|------|
| P0 | 企业微信群机器人 Webhook | 来电摘要、预约、骚扰拦截、异常告警 | MVP 默认通知入口，成本低、接入简单、适合高频商家通知 |
| P1 | 企业微信应用 / 客服能力 | 续费、业务咨询、指令交互、跳转小程序 | 第二阶段建设，承接双向交互和菜单指令 |
| P2 | 微信订阅消息 | 支付、到期、关键服务提醒 | 受模板和用户授权限制，只做关键兜底 |
| P2 | 钉钉 / 短信 | 非企业微信用户或异常兜底 | 避免成为主要成本 |

企业微信能力边界：

- 企业微信群机器人适合发送通知，但不是完整的双向指令机器人。
- 续费、咨询业务、指令处理、跳转小程序等交互能力，应通过企业微信应用、客服能力或小程序链接承接。
- 群机器人发送频率不是无限制，设计上要做限频、合并和重试。当前公开资料常见口径为单机器人约 20 条/分钟，生产环境以企业微信官方后台和接口返回为准。
- “好友数量超过 5000”不是群机器人能力，而是企业微信客户联系 / 外部联系人能力。公开资料常见口径为单成员默认约 5000，可随认证、付费或申请扩容提升；生产环境需以企业微信当前官方规则和账号后台显示为准。

实时通知：

- 工作时间内，有效来电立即推送。
- 重要、紧急、投诉类来电立即推送。
- 骚扰电话默认不实时推送。

延迟通知：

- 深夜普通来电延迟到次日 9:00 推送。
- 午休时段普通来电可汇总到 14:00 推送。
- 周末按用户配置决定是否静默、汇总或照常推送。

每日汇总：

- 默认晚上 20:00 推送。
- 内容包括接听总数、有效来电、骚扰拦截、预约、投诉、重复咨询、建议优化项。

## 13. 风险与待验证事项

| 风险 | 影响 | 应对 |
|------|------|------|
| 运营商 API 自动开通能力无法落地 | 开通体验下降 | 保留一键拨号、教程、客服协助 |
| 171 号码信任度不足 | 客户可能不接或不信任 | 号码认证短信、商家物料、长期申请 95/400 号段 |
| 部分运营商限制条件呼叫转移 | 用户无法顺利接入 | 多号码供应商、公开 Rosie 号码作为备选、客服协助 |
| AI 对话误识别 | 预约错误或答非所问 | 关键信息二次确认、人工转接、摘要可追溯 |
| 企业微信群机器人限频或配置错误 | 商家收不到来电结果 | 通知合并、重试、失败告警，微信订阅消息 / 钉钉 / 短信兜底 |
| 合规和录音告知要求 | 法务风险 | 接听提示、隐私协议、数据留存策略 |
| 真实 PSTN 入站线路暂未就绪 | 无法立即真实手机呼入试点 | 作为商务前置项并行推进 SIP Trunk / DID / IMS，研发先做业务层 MVP |
| jambonz / Pipecat 集成复杂度 | 延迟或媒体流联调受阻 | Rosie webhook、AI greeting、realtime listen verbs 已通过公网验证，后续接真实线路和媒体流 |
| 本地模型效果或延迟不足 | 对话体验差 | DeepSeek 等 API 作为短期兜底，逐步优化本地模型 |

## 14. 版本路线图

### Phase 1：MVP 验证，0 到 10 家商家

- 使用 jambonz + Rosie webhook 完成通信技术链路验证；真实 PSTN 入站线路作为商务前置项并行推进。
- 先用模拟转写和 AI 提取跑通防骚扰、通话记录、摘要、结构化信息、企业微信群机器人通知闭环。
- 找熟人商家试点，重点验证愿不愿意付费和是否真的省事。

### Phase 2：小规模试点，10 到 100 家商家

- 使用 jambonz 管理底层 FreeSWITCH / drachtio，不直接裸写 FreeSWITCH 业务逻辑。
- 开始使用独立号码或小批量号码。
- 完善小程序开通、配置、通话详情和续费。
- 建立骚扰关键词库和人工转接规则。
- 部署 sngrep / HOMER / SIPp，形成通信排障和压测能力。

### Phase 3：商业化扩展，100 到 3000 家商家

- 独立号码优先，批量采购 170/171 号码。
- 部署 jambonz 主备或集群，底层 FreeSWITCH 作为媒体节点。
- 部署 Pipecat Agent Pool，并拆分 STT / LLM / TTS 服务池。
- 提升防骚扰准确率、通话稳定性和通知体验。
- 建立基础运营后台和商家生命周期管理。

### Phase 4：规模化，1 万到 5 万用户

- Kamailio + jambonz 集群 + 多 FreeSWITCH 媒体节点。
- Pipecat Agent Pool + STT / LLM / TTS 模型池。
- 直连运营商 SIP Trunk 或更低成本号码资源。
- 扩展业务人士版，形成商家版与个人版双产品线，并验证声音克隆增值服务转化。
