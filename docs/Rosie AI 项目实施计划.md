# Rosie AI 项目实施计划

版本：v1.0  
依据文档：`Rosie AI 需求文档.md`、`Rosie AI 技术方案.md`  
实施原则：通信技术链路和业务价值分离推进；先借成熟开源项目落地，再逐步优化自研能力。

## 1. 项目目标

Rosie AI 第一阶段目标不是做一个完整通信平台，而是尽快验证一个可付费的 AI 电话前台产品。

产品边界：Rosie 只做接电话，不做主动外拨电话，不做电销系统。最多支持基于真实来电上下文、由商家手动确认或明确授权的单次回拨。

核心目标：

- 使用 jambonz 接入真实 SIP 电话。
- 使用 Pipecat 跑通实时语音 Agent。
- 使用本地开源 STT / LLM / TTS 控制 AI 成本。
- 使用微信小程序完成开通、配置、通话记录和通知。
- 找到 3 到 10 家真实商家试点，验证 30 元/月基础套餐和 +5 元/月声音克隆增值服务。

## 2. 当前定型范围

### 2.1 产品范围

MVP 必做：

- 商家版 30 元/月。
- 业务人士版 30 元/月。
- 老板授权声音克隆增值服务 +5 元/月。
- 微信小程序授权登录。
- 商家基础配置。
- 条件呼叫转移接入：用户原号码不变，Rosie 幕后接入号只承接无应答、忙线、不可及场景。
- AI 自动接听。
- 前 5 秒防骚扰过滤。
- 常见问题回答。
- 预约信息收集和记录。
- 人工转接。
- 通话转写、摘要、关键信息提取。
- 小程序收件箱和定时汇总。
- 通话列表和详情页。
- 基于原始来电上下文的一键回拨入口，必须由商家手动触发并记录日志。

MVP 暂不做：

- 完整 CRM。
- 多坐席客服系统。
- 复杂工单流转。
- 大规模号码自动采购系统。
- 全球多区域正式运营。
- 完整数据看板和营销增长系统。
- 主动外拨电话。
- 批量外呼、陌生号码营销、电话销售 CRM。
- 无真实来电、预约、订单或人工确认上下文的自动回拨。

### 2.2 技术范围

主线技术：

- 通信控制：jambonz。
- 底层媒体：jambonz 管理的 FreeSWITCH / drachtio。
- 实时语音 Agent：Pipecat。
- STT：FunASR + SenseVoice Small。
- LLM：Qwen3-8B 本地，DeepSeek API 兜底。
- TTS：Fun-CosyVoice 3.0，保守备选 CosyVoice 2.0。
- 数据库：PostgreSQL 17。
- 缓存：Valkey 8.x / Redis 7.2.x。
- 对象存储：腾讯云 COS 或 MinIO。
- 监控排障：Prometheus、Grafana、sngrep，试点前引入 HOMER。

## 3. 当前项目判断

截至 2026-04-29，Rosie 侧通信技术链路已经验证：

- `call-webhook` 可被公网访问并返回 jambonz verbs。
- AI greeting 已通过 `ai-agent + DeepSeek API` 跑通。
- `listen` verb 已能生成公网 WebSocket 地址。
- `realtime-voice` 服务公网健康检查通过。
- 多商家幕后接入号映射已能识别 `8613736849910`。

业务层 MVP 已验证：

- 模拟转写入口 `/simulate/call-result` 已完成，可用文本模拟真实 STT 输出。
- AI 摘要和结构化提取已接入，能识别预约意图、优先级、是否需要人工跟进，并可提取“明天下午三点”这类中文时间表达。
- 收件箱 `/inbox` 已完成，来电摘要会进入待处理列表。
- `call_sid` 幂等已完成，同一通电话重复提交会更新原转写、摘要和收件箱条目，不重复生成待办。
- 汇总预览 `/digests/preview` 已完成，可生成老板能直接阅读的每日汇总正文。
- 正式汇总 `/digests/generate` 已完成，会创建汇总历史并将本批 inbox items 标记为 `digested`。
- 汇总历史 `/digests` 已完成，可查询已生成汇总。
- 通知偏好 `/notification-preferences` 已完成，默认每日 20:00 汇总、实时通知关闭、紧急实时提醒开启。

未完成的是“真实 PSTN 电话进入 jambonz”，原因不是 Rosie 代码链路不通，而是缺少真实可入站的 SIP Trunk / DID / 运营商线路资源。该事项归类为商务前置项，不再作为当前研发阻塞项。

当前推进策略：

- 不再为了验证 jambonz 基础能力单独购买海外 DID。
- 海外 DID / SIP Provider 只作为后续全球化或临时兜底选项。
- 研发继续推进业务层 MVP：通话记录、转写、摘要、意图、通知、商家配置。
- 商务并行寻找中国区可入站 SIP Trunk / DID / IMS 线路资源。

## 6. Phase 1：通信技术 POC

周期：第 2 周

目标：验证 Rosie 侧对 jambonz 的 webhook、AI greeting、实时音频入口和接入号映射能力。

### 6.1 任务清单

| 工作项 | 产出 |
|--------|------|
| 部署 jambonz | 可访问管理控制台或配置入口 |
| 配置 jambonz Application | Call Hook / Status Hook 指向 Rosie |
| 配置测试号码 | 被叫号码可映射到 Rosie 应用，真实号码资源由商务补齐 |
| 实现 Rosie Call Webhook | jambonz 呼入后可回调业务后端 |
| 播放固定欢迎语 | 电话侧能听到欢迎语 |
| 接入 AI greeting | DeepSeek API 可生成开场话术 |
| 返回 realtime listen verbs | jambonz 可获得 WebSocket 音频入口 |
| 记录通话事件 | 呼入、接听、挂断事件进入数据库 |
| 线路商务接入 | 并行寻找真实可入站 SIP Trunk / DID / IMS |

### 6.2 当前验收状态

- Rosie 服务端口 `8000`、`8020` 公网健康检查通过。
- `call-webhook` 能根据接入号码识别商家。
- `call-webhook` 能调用 `ai-agent` 生成开场话术。
- webhook response 能返回 `say + listen + hangup`。
- `realtime-voice` 可被公网访问。
- 真实 PSTN 呼入未完成，原因是缺少线路资源，转入 Phase 1B 商务项。

### 6.3 Go / No-Go

研发可以进入业务层 MVP，但真实商家试点前必须满足：

- 至少 1 条真实可入站 SIP Trunk / DID / IMS 线路可用。
- 连续 20 通真实测试呼入成功率大于 95%。
- 主叫、被叫、call_id、接入号记录准确。

## 7. Phase 1B：线路商务接入

周期：并行推进。

目标：找到能把真实 PSTN 来电送入 jambonz 的线路资源。

任务：

- 联系中国区运营商政企客户经理或有资质线路集成商。
- 确认是否提供 SIP Trunk / DID / IMS 入站能力。
- 确认是否支持无应答 / 忙线 / 不可及条件呼叫转移到 Rosie 幕后接入号。
- 明确号码月租、并发、呼入计费、SLA、号码回收、故障赔偿。
- 海外 DID / Telnyx / Twilio 只作为可选兜底，不作为当前必做验证。

退出标准：

- 拿到至少 1 个真实可呼入到 jambonz 的测试号码。
- 完成 20 通真实手机呼入测试。
- 真实音频进入 `realtime-voice`，`audio_bytes > 0`。

## 8. Phase 2：业务层 MVP

周期：第 3 周

目标：即使真实线路暂未就绪，也先把老板真正看到的业务结果做出来。

### 8.1 任务清单

| 工作项 | 产出 |
|--------|------|
| 通话会话模型 | calls、transcripts、summaries、intent、follow_up |
| 模拟转写入口 | 可用文本模拟真实 STT 输出，提前验证业务闭环 |
| AI 摘要 | 提取来电人、诉求、预约时间、重要性、骚扰判断 |
| 行业话术模板 | 至少完成理发店 / 本地生活服务一个模板 |
| 小程序收件箱 | 商家可看到全量来电摘要、分类、优先级和回拨建议 |
| 定时汇总 | 默认每日 20:00 生成汇总，可选午间 + 晚间 |
| 通话详情接口 | 可查询原始通话、转写、摘要和结构化字段 |
| 回拨边界 | 仅展示基于本通来电的手动回拨入口和审计字段 |

### 8.1.1 当前完成状态

已完成：

- 通话转写、摘要、收件箱、汇总相关 SQLite 表结构。
- 模拟转写入口 `/simulate/call-result`。
- AI 摘要和结构化字段提取。
- 收件箱列表 `/inbox`。
- 汇总预览 `/digests/preview`。
- 汇总生成 `/digests/generate`。
- 汇总历史 `/digests`。
- 通知偏好查看和更新 `/notification-preferences`。

待完成：

- 定时汇总触发器，例如 `POST /internal/digest-tick`，由 cron 每分钟调用。
- 通知发送日志和发送通道抽象。
- 微信订阅消息接入。
- 小程序收件箱、汇总历史、通知偏好页面。
- 通话详情查询接口和回拨审计字段。

### 8.2 验收标准

- 输入一段模拟来电文本后，系统能生成摘要和结构化信息。
- 商家能看到来电列表和通话详情。
- 有效来电能进入小程序收件箱。
- 每日汇总能按时生成。
- 骚扰 / 广告类来电能被标记，不触发高优先级通知。
- 所有回拨入口都绑定原始 call_id。

### 8.3 Go / No-Go

进入下一阶段前必须满足：

- 连续 50 条模拟来电文本处理无失败。
- 摘要字段可被老板直接理解。
- 通知内容能支持老板判断是否需要处理。

## 10. Phase 4：真实商家试点

周期：第 7-10 周

目标：验证真实使用、付费意愿和运营问题。

### 10.1 试点范围

建议首批商家：

- 1 家理发店。
- 1 家宠物店。
- 1 家维修 / 家政 / 本地服务商家。

每家试点至少 7 天。

### 10.2 试点指标

| 指标 | 目标 |
|------|------|
| 呼入接听成功率 | 大于 95% |
| 有效通话摘要成功率 | 大于 90% |
| 商家通知触达 | 30 秒内 |
| 预约信息准确率 | 大于 85% |
| 骚扰拦截有效性 | 商家主观认可 |
| 平均响应延迟 | 小于 2 秒 |
| 7 日后愿意继续使用 | 至少 50% |

### 10.3 每日运营动作

- 每天查看失败通话。
- 每天整理误识别样本。
- 每天更新骚扰关键词。
- 每天访谈至少 1 位试点商家。
- 每天复盘延迟、挂断、转接失败。

### 10.4 Go / No-Go

进入商业化前必须满足：

- 至少 3 家商家完成 7 天试点。
- 至少 2 家明确愿意付费或继续试用。
- 主要失败原因可被定位和修复。
- 通信线路没有不可接受的不稳定问题。

## 11. Phase 5：小规模商业化

周期：第 11-16 周

目标：从 10 家扩展到 100 家商家，建立可复制开通和运维体系。

### 11.1 重点任务

- 寻找稳定线路供应商或三大运营商政企线路。
- 建立号码采购、分配、回收流程。
- 部署 jambonz 主备。
- 部署 Pipecat Agent Pool。
- 引入 HOMER 做 SIP 监控。
- 完善运营后台。
- 完善支付、续费、到期停用。
- 完善声音克隆增值服务。
- 建立客服 SOP。

### 11.2 验收标准

- 100 家以内商家可稳定开通。
- 通信问题可在 30 分钟内定位。
- AI 服务异常有兜底，不导致大面积不可用。
- 续费和增值服务计费可闭环。
- 形成商家开通 SOP 和故障处理 SOP。

## 13. 关键风险与应对

| 风险 | 阶段 | 应对 |
|------|------|------|
| 真实 PSTN 入站线路暂未就绪 | Phase 1B | 商务并行推进 SIP Trunk / DID / IMS，研发先做业务层 MVP |
| SIP Trunk 不稳定 | Phase 1B | 同时准备第二供应商，保留详细 SIP 日志 |
| jambonz 媒体流对接 Pipecat 受阻 | Phase 3 | 先用固定音频和云 STT/TTS 模拟，再替换本地模型 |
| 本地模型延迟高 | Phase 2-3 | 实时链路用小模型，摘要异步用大模型，API 兜底 |
| 商家不会设置条件呼叫转移 | Phase 3-4 | 小程序一键拨号、视频教程、客服协助，明确“不换号” |
| AI 误预约 | Phase 4 | 关键信息二次确认，预约默认可人工确认 |
| 微信订阅消息授权不足 | Phase 2-4 | 小程序收件箱保留全量结果，企业微信群机器人 / 钉钉 / 短信作为可选兜底 |
| 企业微信群机器人配置门槛高 | Phase 2-4 | 不作为默认开通流程，仅作为团队商家可选通知 |
| 声音克隆合规风险 | Phase 3+ | 单独授权、明确 AI 身份、可删除 |
| 试点商家不愿付费 | Phase 4 | 先验证痛点行业，调整套餐和卖点 |

## 16. 成功标准

项目第一阶段成功，不以功能数量判断，而以真实商家是否愿意继续使用判断。

最低成功标准：

- 至少 3 家真实商家完成 7 天试点。
- 系统能稳定接听真实电话。
- 商家能收到有效摘要。
- 至少 2 家商家认为 Rosie 确实减少了漏接或骚扰。
- 至少 1 家商家愿意付费或推荐给朋友。

达到以上标准后，再进入 100 家商家的小规模商业化阶段。
