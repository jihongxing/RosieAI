# Rosie AI 项目实施计划

版本：v1.0  
依据文档：`Rosie AI 需求文档.md`、`Rosie AI 技术方案.md`  
实施原则：先跑通真实电话闭环，再做规模化；先借成熟开源项目落地，再逐步优化自研能力。

## 1. 项目目标

Rosie AI 第一阶段目标不是做一个完整通信平台，而是尽快验证一个可付费的 AI 电话前台产品。

产品边界：Rosie 只做接电话，不做主动外拨电话，不做电销系统。最多支持基于真实来电上下文、由商家手动确认或明确授权的单次回拨。

核心目标：

- 使用 jambonz 接入真实 SIP 电话。
- 使用 Pipecat 跑通实时语音 Agent。
- 使用本地开源 STT / LLM / TTS 控制 AI 成本。
- 使用微信小程序完成开通、配置、通话记录和通知。
- 找到 3 到 10 家真实商家试点，验证 30 元/月基础套餐和 +5 元/月声音克隆增值服务。

## 2. 当前定型范围

### 2.1 产品范围

MVP 必做：

- 商家版 30 元/月。
- 业务人士版 30 元/月。
- 老板授权声音克隆增值服务 +5 元/月。
- 微信小程序授权登录。
- 商家基础配置。
- 条件呼叫转移接入：用户原号码不变，Rosie 幕后接入号只承接无应答、忙线、不可及场景。
- AI 自动接听。
- 前 5 秒防骚扰过滤。
- 常见问题回答。
- 预约信息收集和记录。
- 人工转接。
- 通话转写、摘要、关键信息提取。
- 微信 / 企业微信通知。
- 通话列表和详情页。
- 基于原始来电上下文的一键回拨入口，必须由商家手动触发并记录日志。

MVP 暂不做：

- 完整 CRM。
- 多坐席客服系统。
- 复杂工单流转。
- 大规模号码自动采购系统。
- 全球多区域正式运营。
- 完整数据看板和营销增长系统。
- 主动外拨电话。
- 批量外呼、陌生号码营销、电话销售 CRM。
- 无真实来电、预约、订单或人工确认上下文的自动回拨。

### 2.2 技术范围

主线技术：

- 通信控制：jambonz。
- 底层媒体：jambonz 管理的 FreeSWITCH / drachtio。
- 实时语音 Agent：Pipecat。
- STT：FunASR + SenseVoice Small。
- LLM：Qwen3-8B 本地，DeepSeek API 兜底。
- TTS：Fun-CosyVoice 3.0，保守备选 CosyVoice 2.0。
- 数据库：PostgreSQL 17。
- 缓存：Valkey 8.x / Redis 7.2.x。
- 对象存储：腾讯云 COS 或 MinIO。
- 监控排障：Prometheus、Grafana、sngrep，试点前引入 HOMER。

## 3. 总体里程碑

| 阶段 | 周期 | 目标 | 退出标准 |
|------|------|------|----------|
| Phase 0：准备 | 第 1 周 | 环境、供应商、合规和试点资源准备 | 测试 SIP 线路、服务器、小程序主体、试点商家名单就绪 |
| Phase 1：通信 POC | 第 2 周 | jambonz 接入真实电话 | 电话能打进来、播放音频、转人工、挂断并记录事件 |
| Phase 2：AI POC | 第 3 周 | Pipecat 跑通实时 AI 对话 | 电话中完成 STT -> LLM -> TTS 往返 |
| Phase 3：MVP 闭环 | 第 4-6 周 | 产品闭环可用 | 商家配置、预约、摘要、通知、小程序详情可用 |
| Phase 4：真实试点 | 第 7-10 周 | 3 到 10 家商家试用 | 连续 7 天稳定接听，收集付费意愿和问题 |
| Phase 5：小规模商业化 | 第 11-16 周 | 10 到 100 家商家 | 形成可复制开通流程和基础运维体系 |

## 4. Phase 0：准备阶段

周期：第 1 周

目标：把技术、商务、合规、试点资源准备到可以开工的状态。

### 4.1 任务清单

| 工作项 | 负责人 | 产出 |
|--------|--------|------|
| 云服务器选型 | 技术 | 腾讯云账号、测试服务器、GPU 资源预估 |
| 测试 SIP Trunk | 商务 / 技术 | 至少 1 条可呼入测试线路 |
| 测试号码 | 商务 | 至少 1 个可被呼叫或可转接号码 |
| 微信小程序主体 | 产品 / 运营 | 小程序账号、微信支付准备 |
| 试点商家招募 | 运营 | 3 到 10 家候选商家 |
| 合规文案初稿 | 产品 / 法务 | 隐私协议、录音告知、AI 身份告知 |
| 产品边界确认 | 产品 / 法务 / 运营 | 只做入站接听和受控上下文回拨，不做营销外呼 |
| 开源许可证检查 | 技术 / 法务 | jambonz、Pipecat、Qwen3、FunASR、Fun-CosyVoice 许可证记录 |

### 4.2 验收标准

- 测试 SIP 线路可用于真实呼入。
- 至少 1 台通信服务器和 1 台应用 / AI 服务器可用。
- 至少 3 家试点商家同意参与。
- 开场录音告知文案确定。

## 5. Phase 1：通信 POC

周期：第 2 周

目标：使用 jambonz 跑通真实电话链路。

### 5.1 任务清单

| 工作项 | 产出 |
|--------|------|
| 部署 jambonz | 可访问管理控制台或配置入口 |
| 对接测试 SIP Trunk | 电话可进入 jambonz |
| 配置测试号码 | 被叫号码可映射到 Rosie 应用 |
| 实现 Rosie Call Webhook | jambonz 呼入后可回调业务后端 |
| 播放固定欢迎语 | 电话侧能听到欢迎语 |
| 实现挂断 | 后端可控制挂断 |
| 实现人工转接 | 可转接到指定手机号 |
| 记录通话事件 | 呼入、接听、挂断事件进入数据库 |
| 安装 sngrep | 能排查 SIP 信令 |

### 5.2 验收标准

- 使用手机拨打测试号码，jambonz 能稳定接起。
- 电话侧能听到固定音频。
- 后端能拿到主叫、被叫和 call_id。
- 可以从后端触发转人工。
- 通话结束后数据库有完整事件记录。

### 5.3 Go / No-Go

进入下一阶段前必须满足：

- 连续 20 通测试呼入成功率大于 95%。
- 不能存在无法定位原因的呼入失败。
- 主叫、被叫、call_id 记录准确。

## 6. Phase 2：AI POC

周期：第 3 周

目标：使用 Pipecat 跑通电话里的实时 AI 对话。

### 6.1 任务清单

| 工作项 | 产出 |
|--------|------|
| 部署 Pipecat Agent | 可接收 jambonz 媒体流 |
| 接入 STT | FunASR / SenseVoice 可识别电话音频 |
| 接入 LLM | Qwen3-8B 可生成回复 |
| 接入 TTS | Fun-CosyVoice 可合成音频 |
| 建立音频回传 | AI 回复能回到电话侧 |
| 实现基础打断 | 用户说话时可中断 AI 播放 |
| 实现兜底话术 | STT/LLM/TTS 超时可播放固定话术 |
| 接入 DeepSeek 兜底 | 本地 LLM 异常时可切换 API |

### 6.2 验收标准

- 电话中可完成至少 3 轮自然问答。
- 平均响应延迟可接受，目标小于 2 秒。
- STT 能识别普通中文电话语音。
- TTS 音频能稳定回放。
- 本地 LLM 异常时不导致通话挂死。

### 6.3 Go / No-Go

进入下一阶段前必须满足：

- 连续 20 通 AI 测试通话无进程崩溃。
- STT -> LLM -> TTS 链路可重复运行。
- 延迟、失败原因可通过日志定位。

## 7. Phase 3：MVP 闭环

周期：第 4-6 周

目标：完成商家可真实使用的产品闭环。

### 7.1 后端任务

| 工作项 | 产出 |
|--------|------|
| 用户服务 | 用户、套餐、状态 |
| 商家服务 | 店名、服务、营业时间、FAQ、转接号码 |
| 号码服务 | 号码与 merchant_id 映射 |
| 预约服务 | 时间槽、预约创建、冲突判断 |
| 通话服务 | 录音、转写、摘要、结构化信息 |
| 通知服务 | 微信 / 企业微信推送 |
| 声音服务 | 声音克隆授权、试听、启用、删除 |
| 管理后台最小版 | 商家、号码、通话异常查看 |

### 7.2 小程序任务

| 页面 | MVP 内容 |
|------|----------|
| 首页 | 服务状态、测试入口、今日接听、今日拦截 |
| 开通页 | 套餐、支付、幕后接入号、条件呼叫转移引导 |
| 商家配置页 | 店铺信息、营业时间、服务项目、FAQ |
| 通话列表 | 有效来电、骚扰来电、未处理来电 |
| 通话详情 | 摘要、录音、转写、关键信息、回拨 |
| 声音设置 | 购买、授权、录音、试听、启用、停用 |
| 续费页 | 到期时间、套餐、增值服务 |

### 7.3 AI 任务

| 工作项 | 产出 |
|--------|------|
| 防骚扰规则 | 号码黑名单、关键词、观察模式 |
| 商家 Prompt | 根据商家配置生成系统提示 |
| 预约 Function | check_availability、create_appointment |
| 转人工策略 | 投诉、紧急、无法识别时转接 |
| 摘要提取 | 姓名、电话、时间、服务、诉求、优先级 |
| 固定话术缓存 | 欢迎语、等待语、确认语 |

### 7.4 验收标准

- 商家可在小程序完成基础配置。
- 客户来电后 AI 能识别咨询 / 预约 / 骚扰。
- 有效通话结束后 30 秒内推送摘要。
- 预约能写入数据库并通知商家。
- 商家可查看录音、转写、摘要。
- 声音克隆可完成授权、录制、试听和启停。

## 8. Phase 4：真实商家试点

周期：第 7-10 周

目标：验证真实使用、付费意愿和运营问题。

### 8.1 试点范围

建议首批商家：

- 1 家理发店。
- 1 家宠物店。
- 1 家维修 / 家政 / 本地服务商家。

每家试点至少 7 天。

### 8.2 试点指标

| 指标 | 目标 |
|------|------|
| 呼入接听成功率 | 大于 95% |
| 有效通话摘要成功率 | 大于 90% |
| 商家通知触达 | 30 秒内 |
| 预约信息准确率 | 大于 85% |
| 骚扰拦截有效性 | 商家主观认可 |
| 平均响应延迟 | 小于 2 秒 |
| 7 日后愿意继续使用 | 至少 50% |

### 8.3 每日运营动作

- 每天查看失败通话。
- 每天整理误识别样本。
- 每天更新骚扰关键词。
- 每天访谈至少 1 位试点商家。
- 每天复盘延迟、挂断、转接失败。

### 8.4 Go / No-Go

进入商业化前必须满足：

- 至少 3 家商家完成 7 天试点。
- 至少 2 家明确愿意付费或继续试用。
- 主要失败原因可被定位和修复。
- 通信线路没有不可接受的不稳定问题。

## 9. Phase 5：小规模商业化

周期：第 11-16 周

目标：从 10 家扩展到 100 家商家，建立可复制开通和运维体系。

### 9.1 重点任务

- 寻找稳定线路供应商或三大运营商政企线路。
- 建立号码采购、分配、回收流程。
- 部署 jambonz 主备。
- 部署 Pipecat Agent Pool。
- 引入 HOMER 做 SIP 监控。
- 完善运营后台。
- 完善支付、续费、到期停用。
- 完善声音克隆增值服务。
- 建立客服 SOP。

### 9.2 验收标准

- 100 家以内商家可稳定开通。
- 通信问题可在 30 分钟内定位。
- AI 服务异常有兜底，不导致大面积不可用。
- 续费和增值服务计费可闭环。
- 形成商家开通 SOP 和故障处理 SOP。

## 11. 关键风险与应对

| 风险 | 阶段 | 应对 |
|------|------|------|
| SIP Trunk 不稳定 | Phase 1 | 同时准备第二供应商，保留详细 SIP 日志 |
| jambonz 媒体流对接 Pipecat 受阻 | Phase 2 | 先用固定音频和云 STT/TTS 模拟，再替换本地模型 |
| 本地模型延迟高 | Phase 2-3 | 实时链路用小模型，摘要异步用大模型，API 兜底 |
| 商家不会设置条件呼叫转移 | Phase 3-4 | 小程序一键拨号、视频教程、客服协助，明确“不换号” |
| AI 误预约 | Phase 4 | 关键信息二次确认，预约默认可人工确认 |
| 微信订阅消息授权不足 | Phase 3-4 | 企业微信、钉钉、短信兜底 |
| 声音克隆合规风险 | Phase 3+ | 单独授权、明确 AI 身份、可删除 |
| 试点商家不愿付费 | Phase 4 | 先验证痛点行业，调整套餐和卖点 |

## 12. 每周推进机制

每周固定节奏：

- 周一：确认本周目标和阻塞。
- 周三：中期检查，处理跨团队问题。
- 周五：演示本周可运行成果。
- 每日：记录测试通话、失败原因和修复状态。

每周必须产出：

- 可运行版本。
- 问题清单。
- 指标数据。
- 下周计划。

## 13. 第一阶段立即行动清单

从现在开始的第一周，优先做这些事：

1. 确认腾讯云账号和两台测试服务器。
2. 找到 1 条测试 SIP Trunk 或可呼入 DID。
3. 部署 jambonz。
4. 写最小 Rosie Call Webhook。
5. 准备一个固定欢迎语音频。
6. 完成一次真实手机呼入测试；如果暂时无法设置条件呼叫转移，先直接拨打 Rosie 幕后接入号验证链路。
7. 招募 3 家试点商家。
8. 整理录音告知和隐私协议初稿。
9. 检查 jambonz、Pipecat、Qwen3、FunASR、Fun-CosyVoice 许可证。
10. 建立项目看板，按本文档拆任务。

## 14. 成功标准

项目第一阶段成功，不以功能数量判断，而以真实商家是否愿意继续使用判断。

最低成功标准：

- 至少 3 家真实商家完成 7 天试点。
- 系统能稳定接听真实电话。
- 商家能收到有效摘要。
- 至少 2 家商家认为 Rosie 确实减少了漏接或骚扰。
- 至少 1 家商家愿意付费或推荐给朋友。

达到以上标准后，再进入 100 家商家的小规模商业化阶段。
