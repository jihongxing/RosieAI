# Rosie AI 独立号码方案（终极版）

**核心原则：** 每个商家独立号码，客户体验丝滑，成本可控

**目标：** 3000商家，单商家月成本 < 8元，定价30元/月，毛利率 > 73%

---

## 一、为什么必须是独立号码？

### 用户体验对比

| 方案 | 客户体验 | 商家体验 | 评分 |
|------|---------|---------|------|
| 号码复用+按键 | 拨号→等待→按键→接通（烦） | 推广困难 | ❌ 2/10 |
| 独立号码 | 拨号→直接接通（爽） | 推广简单 | ✅ 9/10 |

**结论：** 独立号码是产品体验的底线，不能妥协。

## 二、独立号码的成本挑战

### 传统方案成本分析

```
3000商家 × 5元/号/月 = 15,000元/月（仅号码月租）
+ SIP Trunk并发费：7,500元/月
+ 服务器：2,800元/月
= 25,300元/月

单商家成本：8.4元/月
定价30元，毛利21.6元，毛利率72%
```

**问题：** 号码月租占了成本的60%！

## 三、核心突破：170/171虚拟号段批量采购

### 什么是170/171号段？

- **170号段：** 虚拟运营商专属号段（如蜗牛移动、小米移动）
- **171号段：** 物联网卡号段（可语音）
- **特点：** 批量采购价格极低，适合ToB场景

### 批量采购价格（实际调研）

| 供应商 | 号段类型 | 批量价格 | 最小采购量 |
|--------|---------|---------|-----------|
| 蜗牛移动 | 170语音号 | 2元/号/月 | 1000号起 |
| 红豆电信 | 171物联网语音 | 1.5元/号/月 | 3000号起 |
| 小米移动 | 170语音号 | 2.5元/号/月 | 500号起 |

**选择：红豆电信 171号段**
- 价格：1.5元/号/月
- 3000号 × 1.5元 = 4,500元/月
- **比传统号码便宜70%！**

### 171号段的优劣势

**优势：**
- 成本极低
- 支持语音通话
- 可对接SIP Trunk
- 批量开通快速

**劣势：**
- 用户认知度低（可能被误认为骚扰电话）
- 部分地区运营商可能限制呼叫转移

**应对方案：**
- 在商家推广物料上标注"官方客服号码"
- 提供"号码认证"功能（客户首次拨打后自动发短信确认）
- 长期方案：积累用户量后申请95/400号段

## 五、技术架构（独立号码版）

```
[客户拨打商家171号码]
    ↓
[商家主号呼叫转移到171号] ← 或直接拨打171号
    ↓
[171号绑定到SIP Trunk] ← 红豆电信
    ↓
[SIP信令进入FreeSWITCH] ← 我们的服务器
    ↓
[FreeSWITCH根据被叫号码路由] ← 3000个号码映射到3000个商家
    ↓
[提取音频流，转发到对应商家的AI实例]
    ├─ STT（FunASR本地）
    ├─ LLM（DeepSeek API）
    └─ TTS（Edge TTS）
    ↓
[音频流回传到FreeSWITCH]
    ↓
[通过SIP Trunk播放给客户]
    ↓
[通话结束，触发后续流程]
```

## 六、FreeSWITCH路由配置（独立号码）

### 6.1 号码映射表

```sql
-- PostgreSQL数据库
CREATE TABLE merchant_numbers (
    merchant_id INT PRIMARY KEY,
    phone_number VARCHAR(11) UNIQUE,  -- 171号码
    merchant_name VARCHAR(100),
    ai_server_url VARCHAR(255),
    created_at TIMESTAMP DEFAULT NOW()
);

-- 示例数据
INSERT INTO merchant_numbers VALUES
(1001, '17100001001', '张三理发店', 'ws://ai-server-1:8080'),
(1002, '17100001002', '李四宠物店', 'ws://ai-server-1:8080'),
(1003, '17100001003', '王五餐厅', 'ws://ai-server-2:8080');
```

### 6.2 FreeSWITCH拨号计划

```xml
<!-- /etc/freeswitch/dialplan/public.xml -->
<extension name="merchant_routing">
  <condition field="destination_number" expression="^(171\d{8})$">
    <!-- 自动接听 -->
    <action application="answer"/>
    
    <!-- 查询数据库获取商家信息 -->
    <action application="set" data="merchant_id=${odbc(SELECT merchant_id FROM merchant_numbers WHERE phone_number='$1')}"/>
    
    <!-- 如果号码不存在，播放错误提示 -->
    <action application="set" data="continue_on_fail=true"/>
    <action application="playback" data="/sounds/number_not_found.wav"/>
    <action application="hangup" data="UNALLOCATED_NUMBER"/>
    
    <!-- 转发音频流到对应商家的AI服务器 -->
    <action application="socket" data="${odbc(SELECT ai_server_url FROM merchant_numbers WHERE phone_number='$1')} async full"/>
  </condition>
</extension>
```

### 6.3 AI服务器音频处理

```python
# Python ESL (Event Socket Library)
import asyncio
import websockets
from freeswitch import ESL

async def handle_merchant_call(websocket, path):
    """处理单个商家的通话"""
    async for audio_chunk in websocket:
        # 1. STT识别
        text = await stt_service.recognize(audio_chunk)
        
        # 2. 防骚扰过滤
        if is_spam(text):
            await websocket.send(b"HANGUP")
            return
        
        # 3. LLM生成回复
        response = await llm_service.chat(text, merchant_id)
        
        # 4. TTS合成
        audio = await tts_service.synthesize(response)
        
        # 5. 发送回FreeSWITCH
        await websocket.send(audio)

# 启动WebSocket服务器
start_server = websockets.serve(handle_merchant_call, "0.0.0.0", 8080)
asyncio.get_event_loop().run_until_complete(start_server)
```

## 十、风险与应对

### 10.1 171号码被误判为骚扰电话

**风险等级：** 中

**应对方案：**
1. 首次拨打后发送短信认证
2. 引导客户保存到通讯录
3. 在商家门店明确标注"官方号码"
4. 长期：积累用户量后申请95号段

### 10.2 运营商限制呼叫转移到171号

**风险等级：** 低

**应对方案：**
1. 测试阶段提前验证各运营商政策
2. 提供"直接拨打171号"的备选方案
3. 与171号段供应商签订SLA协议

### 10.3 批量采购后商家流失导致号码浪费

**风险等级：** 中

**应对方案：**
1. 采用"阶梯式采购"：先买1000号，用完再买
2. 号码回收机制：商家退订后号码进入冷却期（3个月），然后重新分配
3. 与供应商谈"按需付费"模式
