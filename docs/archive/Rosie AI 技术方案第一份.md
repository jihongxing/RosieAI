# Rosie AI 技术方案文档（最稳技术组合）

**原则：** 绝对不搞技术炫技，只做 API 缝合，追求极低延迟与高稳定性。

## 1. 技术栈选型

- **通信网关：** 阿里云语音服务 (语音隐私号 AXB) —— 解决国内通信合规性，稳定。
    
- **语音转文字 (STT)：** 火山引擎 (字节跳动) 流式识别 —— 国内目前延迟最低，对口音支持好。
    
- **文字转语音 (TTS)：** 火山引擎 —— 声音最有“人味”，支持多种情绪。
    
- **对话大脑 (LLM)：** DeepSeek-V3 API —— 性价比极高，中文逻辑极强，支持 Function Calling。
    
- **逻辑引擎/闭环：** Python (FastAPI) + 飞书多维表格 (Bitable) 作为“伪CRM”。
    
- **通知系统：** 阿里云短信 + 飞书/企微机器人 Webhook。

## 3. 核心模块实现方案

### 3.1 极简知识库方案 (No RAG)

- **方案：** 放弃复杂的向量数据库。
    
- **执行：** 将商家的文本配置直接塞进 LLM 的 `System Prompt`。
    
- **理由：** 商家信息通常不超过 2000 字，Context Window 完全覆盖，响应更准、更稳。
    

### 3.2 预约规则引擎

- **逻辑：** 开发者预设一套 JSON 结构描述营业时间（如 `{"Sat": "Closed"}`）。
    
- **交互：** 1. AI 在对话中通过 `Function Calling` 尝试调用 `check_availability`。 2. 后端检查逻辑引擎，返回“可预订”或“已满”。 3. AI 引导客户完成预约。
    

### 3.3 自动化行动闭环 (The 3rd Step)

1. **挂断回调：** 通信网关触发 `on_call_end` 事件。
    
2. **信息提取：** 调用 LLM 对录音文本进行 Structuring，提取：`姓名`、`手机`、`时间`、`诉求`。
    
3. **写入数据：** 通过 API 将记录写入**飞书多维表格**（商家直接把这个表当成后台）。
    
4. **下发通知：** 调用阿里云短信 API 发送确认信息给客户；通过 Webhook 推送给商家。
    

## 4. 关键技术指标

- **端到端延迟：** 目标控制在 800ms - 1.2s 以内（STT 流式 + Groq/DeepSeek 极速推理）。
    
- **稳定性：** 通信网关 99.9% 可用性。
    
- **兜底机制：** 若 LLM 响应超过 3 秒，自动播放“信号不好，我正在为您转接人工”并触发 PSTN 转接。
    

## 5. 成本预估（单通电话）

- **通信费：** 约 0.1 元/分钟（阿里云）。
    
- **模型费：** DeepSeek 极低（约 0.01 元/次）。
    
- **语音费：** 火山引擎约 0.05 元/分钟。
    
- **综合成本：** 约为 0.2 元/通电话。商家包月收 199-299 元，毛利极高。
